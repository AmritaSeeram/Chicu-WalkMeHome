What actually crosses the boundary? +

The group coordinator receives the missed friend’s last known point and passes it to personal agents so they can compute ETA. Personal agents return only student ID, ETA, and availability when polled. Public chat messages use a place label and checked outcomes. Agents currently share a process; these are code-level boundaries, not process isolation.

A FEW THINGS TO KNOW

Built thoughtfully.
Described honestly.

Is this a live safety service? +

No. This landing page offers a simulated walkthrough. The repository describes bot and model adapters verified against fakes, not real Telegram or Claude services. This checkout also lacks parts of the documented engine, simulator, and bot source tree.

Does it continuously track me? +

The design uses locations you send through Telegram after opting in. It does not describe continuous background tracking. Locations may be stale; ETA is a straight-line walking estimate. This website does not request your location.

Will it automatically call emergency services? +

No. The design surfaces contact information; it does not make an emergency call or establish that someone is safe. For immediate danger, contact emergency services directly. Official ASU contact information ↗

What does the model decide? +

Claude can parse a shared plan and optionally reword a checked message. Code validates plans, ranks friends, enforces permissions, manages timeouts, and selects the next step. A wording failure falls back to a template.
